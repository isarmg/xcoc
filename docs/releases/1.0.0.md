# xcoc 1.0.0

Windows 静态媒体依赖在编译前复制为独立文件，保留原 vcpkg 构建目录；编译器和发行清单使用相同的已核对前缀。实际 NTFS 硬链接、目录联接拒绝与原生安装验收由当前 Windows CI 执行。

正式资产见 [xcoc v1.0.0](https://github.com/isarmg/xcoc/releases/tag/v1.0.0)。构建、运行与安装验收证据以该标签指向的精确源码和对应官方工作流为准。

## 变更

- 精确消费官方 xcsc 1.0.0；已有业务命令统一 --format human|json|ndjson，成功、失败与实际提交阶段都有结果。
- 受保护 stdin 使用公共有界读取与截止时间；交互授权码隐藏输入。
- iOS 等待摄像头授权的启动请求可取消，旧授权、连接和编码失败回调不能改变新的采集会话；未确认关闭保留句柄并阻止重新启动、配对，支持明确重试。
- iOS 原生结果校验 ABI、状态、指针和长度，C 声明由精确固定的公共 Rust ABI 生成核验。
- 同步桌面安装器、Android / iOS 和原生打包软件版本。

公共客户端源固定为 `6fca4299f5c34a79db1c7bd4e889b418d2a58e2d`。软件补丁号独立于业务协议、持久状态与 FFI ABI。

- Linux 通过真实 pkg-config 传递 OpenSSL 的静态压缩依赖，并保存对应库与许可说明，避免缺失 zlib / zstd 引用。
- iOS 权限、帧、失败与停止状态按会话归属处理；关闭未确认时保留原句柄并禁止替换，允许重试停止。

公共发行工具固定为 `79d13d30a5941b422042a6027e3c4225325e9da8`，使用实际构建目标的运行依赖图和原始许可证；机器 JSON 固定采用 UTF-8。

Windows FFmpeg 版权文件按固定 vcpkg 辅助程序的完整生成结果核验，仅接受对应 LF 或 CRLF 输出；发行物另外保留两份上游原始许可文件及其哈希。

## 验证与交付

各平台的编译、原生运行和安装生命周期由相应平台工作流验证。正式包的外部 SHA256 与包内完整清单绑定全部交付文件、运行依赖及原始许可证；公开版本的验证结果以对应 v1.0.0 Release 和最终源码工作流记录为准。
